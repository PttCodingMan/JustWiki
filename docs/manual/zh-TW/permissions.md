# 權限與帳號

## 角色

每個帳號有一個全站角色：

| 角色 | 可以做的事 |
|------|-----------|
| **admin** | 所有頁面完整權限，並可進入 **管理** 頁面 |
| **editor** | 預設可閱讀與編輯所有未設限的頁面，可建立頁面 |
| **viewer** | 唯讀；即使頁面權限給了寫入，也只能讀 |

管理員在 **管理 → 使用者** 建立帳號與指派角色。

## 頁面權限（ACL）

沒設權限的頁面對所有登入者開放（editor 可編輯、viewer 可讀）。需要限制時，在頁面的 **⋯ 更多操作 → 管理權限** 加入使用者或群組，並給予下列其中一種權限：

| 權限 | 意義 |
|------|------|
| **讀取** | 可以看 |
| **寫入** | 可以編輯內容 |
| **管理** | 寫入之外，還能修改這頁的權限、設為公開，以及把頁面搬到權限不同的位置 |

規則：

- **一旦設了權限，就只有清單上的人看得到。** 沒列在清單上的人（除了管理員）會完全看不到這頁，搜尋、頁面樹、關係圖、AI 問答也都不會出現
- **子頁面繼承父頁面。** 子頁面沒有自己的權限設定時，沿用最近一個有設定的上層頁面；子頁面自己有設定時，以子頁面的為準
- **同一個人符合多列時取最寬鬆的。** 例如個人給讀取、所屬群組給寫入，結果是寫入
- **viewer 最多只能讀**，**admin 不受權限限制**
- 未設限的頁面，由建立者負責管理；設了權限的區域內，只有被明確給予「管理」的人才能調整

:::tip
實務上常見的做法是在頂層建一個「人資」或「財務」頁面並設好權限，相關文件都建在它底下，就會自動繼承同一組權限。
:::

把頁面搬到別的父頁面底下時，它繼承的權限也會跟著改變，所以這個動作需要「管理」權限。

## 群組

管理員在 **管理 → 群組** 建立群組並加入成員，之後在頁面權限裡就能一次授權整個群組。刪除群組時，所有引用它的權限設定也會一併移除。

## 公開頁面

想把某頁分享給沒有帳號的人：

1. 在 **⋯ 更多操作** 選 **設為公開**（需要「管理」權限）
2. 選 **複製公開連結**，網址格式是 `/public/page/<slug>`

公開頁面以精簡的唯讀版面呈現，不需要登入。匿名存取有每個 IP 每分鐘 60 次的速率限制。要收回時選 **設為私人** 即可。

## 匿名瀏覽（整站公開）

如果想讓整個 wiki 不登入就能讀（例如公開的專案文件，或像這個 demo 站），在伺服器設定 `ANONYMOUS_READ=true`。未登入的訪客會被當成 viewer：

- 可以瀏覽頁面樹、搜尋、關係圖、最近變更，以及沒有設權限的頁面
- 編輯、留言、書籤、追蹤、AI 問答與管理功能仍然需要登入

## 登入方式

| 方式 | 說明 |
|------|------|
| 本機帳號 | 帳號密碼登入，密碼以 bcrypt 雜湊；登入有速率限制防暴力破解 |
| OIDC SSO | Google、GitHub，以及任何標準 OIDC 服務（Keycloak、Authentik、Okta、Auth0…），採 PKCE |
| LDAP / AD | 綁定企業目錄，自動對應 email 與顯示名稱，可同步群組 |

SSO 預設是 **邀請制**：管理員在 **管理 → 使用者 → 邀請 (SSO)** 先用 email 建立帳號，對方用 SSO 登入時以 email 配對。也可以設定成首次登入自動建立帳號，並以 email 白名單、網域或群組限制誰能登入。設定方式見 [[zh-admin|管理員指南]]。

## 個人設定

點右上角的個人選單進入 **個人檔案**：

- 修改顯示名稱、email 與自我介紹（支援 Markdown、wikilink、@提及，會顯示在你的公開個人頁 `/u/<使用者名稱>`）
- 變更密碼——變更後其他裝置上的登入都會失效
- 管理 **API 金鑰**（見 [[zh-developer|開發者指南]]）
